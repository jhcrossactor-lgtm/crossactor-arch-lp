# crossactor-arch-lp — CROSSACTOR サービスサイト（3D VR / Web / AI）

CROSSACTOR の **3D VR パース制作・Webサイト/LP制作・AI導入/活用の相談** を紹介し、そのまま相談につなげるサイト。
サイト自体の動きを、Web制作の実例として見せる構成にしている。

- **トップ**：線だけの3Dモデルが「家 → Webサイト → AIネットワーク」と組み替わり、見出しの語（建築／Web／AI）も連動する。カーソルで線が逃げ、クリックで次の形に組み替わる
- **3D VR**：スクロールで図面 → 構造 → 完成 → VR と建物が立ち上がる演出と、360度写真のビフォーアフター比較
- **Web**：「このページも作品のひとつです」として、サイト内の演出をそのまま実例として紹介
- **相談診断**：質問に答えると相談メモと「最初の一歩」が出て、Googleフォームを入力済みの状態で開ける

**コピーは公開中のポートフォリオサイト（jhcrossactor-lgtm.github.io/portfolio）をもとにした下書き**。Web制作・AI相談のサービス内容は仮の文面。

## 動かす

```bash
python -m http.server 8124 -d .
```

`http://localhost:8124` を開く。ビルド不要・外部CDN無し（フォントも同梱）の素の HTML/CSS/JS。

## 相談につなげる導線

| 場所 | 行き先 |
|---|---|
| ナビの「無料で相談」・トップの「30秒の相談診断をする」・固定の相談ボタン | 相談診断の最初から |
| 各サービスカードの「この内容で相談する」・3D VR / ショーケースの相談ボタン | 相談診断（サービスの質問を飛ばして、そのサービスの質問から） |
| 相談診断の結果「この内容でフォームを開く」 | Googleフォーム（ご相談の種類と相談メモを入力済み） |
| CONTACT の「フォームで直接相談する」 | Googleフォーム（空欄） |

固定の相談ボタンは、トップを過ぎると現れ、相談診断と CONTACT が見えている間は隠れる。

相談診断は**ルールベース**（回答の組み合わせで文面を出すだけで、AI は使っていない）。「AI診断」とは表記しないこと。
質問・選択肢・「最初の一歩」の文面は `consult.js` の `QUESTIONS` / `FLOW` / `FIRST_STEP` で編集する。

## Googleフォームのつなぎ方

1. Googleフォームを新規作成し、次の質問を作る（必須にする項目は任意）
   - お名前（記述式）
   - メールアドレス（記述式、または「メールアドレスを収集する」をオン）
   - 会社名（記述式・任意）
   - **ご相談の種類**（記述式）
   - **ご相談内容**（段落）
2. 右上の「︙」→「事前入力した URL を取得」を開き、「ご相談の種類」に `A`、「ご相談内容」に `B` と入れて「リンクを取得」
3. コピーされた URL は次の形になっている
   `https://docs.google.com/forms/d/e/XXXX/viewform?usp=pp_url&entry.111111=A&entry.222222=B`
4. `consult.js` 先頭の `CONTACT` に書き写す
   ```js
   const CONTACT = {
     formUrl: 'https://docs.google.com/forms/d/e/XXXX/viewform',
     entries: { service: 'entry.111111', memo: 'entry.222222' },
   };
   ```
5. 回答の通知は、フォームの「回答」タブ →「︙」→「新しい回答についてのメール通知を受け取る」

`formUrl` が空のあいだは、「フォームを開く」を押すと相談メモをコピーして「未設定」と表示する。

## スクロール演出（SEQUENCE）

`.seq` は `height:420vh`、中身の `.seq__stage` を sticky で固定し、通過中のスクロール量を 0→1 の進行度 `p` にしている。

| 進行度 | 起きること |
|---|---|
| 0 – 0.20 | 立面図の線が1本ずつ引かれる（図面を薄く敷く） |
| 0.22 – 0.42 | 構造材（柱・胴差し・小屋束・筋かい）の線が引かれる |
| 0.36 – 0.52 | 骨組みの写真が下から立ち上がる |
| 0.52 – 0.70 | 完成パースが左から塗られる |
| 0.76 – | VR 表示。フレーム上でマウスを動かすと見回せる |

尺を変えたいときは `.seq` の `height` を変える。

## 動作確認

Chromium（アプリ内ブラウザ）で確認した内容。

- 読み込み・外部通信：リソース 11件すべて成功、外部CDNへの通信なし、同梱フォント 3書体とも読み込み済み
- SEQUENCE：スクロール前に図面の線が自動で描かれる／進行度 0.32・0.47・0.6・0.85・0.92 で、構造線 → 骨組み写真の立ち上がり → 完成パースの塗り → VR 表示の順に切り替わることを数値と画面で確認
- BEFORE / AFTER：つまみで 25% に移動（`aria-valuenow` も追従）、画像ドラッグで 200px 回転、タブ切り替えで画像とラベルが入れ替わる
- レイアウト：デスクトップ（1134px）とスマホ幅で横スクロールなし、ヒーローの要素どうしの重なりなし
- 素材スクリプト：`tools/build_assets.py` の再実行で全素材が再生成される

アプリ内ブラウザはペインが描画されていないとスクロール連動の更新が止まるため、スクロール直後のスクリーンショットは1段階遅れる。
連続したアニメーションのなめらかさは、実ブラウザで一度スクロールして確認すること。

## HERO LAB（トップの別パターン）

`hero-lab/` に、トップの「動きの部分」だけを差し替えた比較用ページを5つ置いている。本番の `index.html` とは独立。
見出し・ボタン・ナビの骨格はそろえてあり、動きと見た目の違いだけで比べられる。

`http://localhost:8124/hero-lab/` が一覧。各ページ下のバー（または ← → キー）で切り替え。

| ファイル | 名前 | 動き | 見た目 |
|---|---|---|---|
| `01-neural.html` | NEURAL FIELD | 粒子がネットワーク状につながり、ときどき「AI / 3D VR / WEB」の文字に集まる。カーソルに線、クリックで信号 | 深い紺、シアン〜紫 |
| `02-terminal.html` | AI TERMINAL | ターミナルに相談が打ち込まれ、手順と提案が返る。背景に言葉が立ちのぼり、見出しにグリッチ | 黒×蛍光グリーン、走査線 |
| `03-grid.html` | HORIZON GRID | グリッドの上を前進し、ワイヤーフレームのビルが立ち上がる。マウスで進路、クリックで加速 | 紫の地平線、マゼンタ×シアン |
| `04-aurora.html` | LIQUID AURORA | 虹色の液体の球体がカーソルの方へふくらみ、すりガラスのカードが漂う | ライトテーマ、グラデーション＋粒子感 |
| `05-scan.html` | VISION SCAN | 完成パースをレーザーが走査。未走査は輪郭線、走査済みは写真。通過した物にラベル。カーソルがレンズ | HUD、アンバー×シアン |

- すべてライブラリ無しの Canvas 2D / CSS。共通部品は `lab.css`、切替バーは `lab.js`
- 02 の会話と 05 の検出ラベルは**演出**（台本と手置きの位置で、AI は動いていない）。ページ内にもその旨を表示している
- 05 のラベル位置は `render-living.webp` を 10% 刻みの方眼で見て置いた。画像を差し替えたら `OBJECTS` の `box` を直す
- 本番に採用するときは、選んだパターンの `<section class="stage">` とスクリプトを `index.html` のヒーローと入れ替える
